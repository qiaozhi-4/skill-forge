# AI 工程提示词集

本文整理了 7 组适用于各类 AI 助手的软件开发提示词，涵盖应用开发、代码库重构、问题排查、系统设计、性能优化、多角色协作和 UI 组件开发。每组都包含可直接使用的中文提示词和实践建议。

## 使用说明

提示词中的“这个产品”“这段代码”等表述依赖当前对话上下文。使用时请一并提供相关需求、代码或项目背景；也可以把这些表述替换成具体内容。

## 1. 从零构建完整应用

```text
请像一名资深全栈工程师一样，构建一个可用于生产环境的应用。先设计系统架构，再实现一个精简且可扩展的版本。请包含：架构、文件结构、数据库 schema、API 端点、UI 架构和完整代码。请按照真实创业团队 MVP 的标准来设计。
```

**建议：**明确写出“精简但可扩展”（minimal but scalable）。否则，结果可能臃肿，也可能只是一个很快就会出问题的玩具版本。

## 2. 理解代码库并重构

```text
请像一名刚加入陌生代码库的资深工程师一样工作。先理解项目架构和数据流，再找出结构问题、重复代码、性能瓶颈和可维护性风险。请提供：架构概览、问题区域、重构策略和改进后的代码。保持现有功能不变。
```

**建议：**保留“保持现有功能不变”这一要求。省略后，AI 助手可能会顺手“改进”那些本来需要保持不变的逻辑。

## 3. 资深工程师式调试

```text
请像一名正在调查生产环境故障的资深调试工程师一样工作。仔细分析代码，逐步推理，找出根因并提出可靠的解决方案。请说明：代码当前的行为、问题所在、失败原因和边界情况，并提供修复后的生产级代码。
```

**建议：**保留“逐步推理”这一要求。它能促使 AI 助手顺着逻辑追查，而不是凭模式匹配猜测；这样更容易发现真实问题。

## 4. 系统设计与实现

```text
请像一名资深系统架构师一样工作。为这个产品设计一个可扩展的系统，再构建一个最精简的生产可用版本。请包含：架构、组件结构、数据流、API 设计、数据库 schema、缓存策略和实现代码。
```

**建议：**开始实现新功能前先运行这条提示词。在提示阶段发现糟糕的架构决策，远比开发两周后才发现代价小。

## 5. 性能优化

```text
请像一名性能工程师一样优化这段代码。目标是提升速度、降低内存占用并增强可扩展性。找出性能瓶颈、低效逻辑和不必要的渲染。请提供：性能问题、优化策略和改进后的代码。
```

**建议：**贴出实际运行缓慢的函数，而不是只描述问题。“我的应用很慢”通常只能得到宽泛建议；提供真实代码才能得到有针对性的修复方案。

## 6. 多角色协作工作流

```text
请由 4 个协作智能体共同完成任务：架构师、工程师、审查者和优化者。架构师负责设计系统，工程师负责实现，审查者负责质量检查，优化者负责提升性能。请依次给出：架构方案、实现、审查反馈和最终优化版本。
```

**建议：**这种方式比单轮提示更慢，但能发现更多问题。“审查者”会真正检查并质疑“工程师”的输出，而不是直接照单全收。

## 7. 生产级 UI 组件

```text
请像一名资深前端工程师一样，构建可复用、无障碍且可用于生产环境的 UI 组件。请考虑：加载状态、边界情况、响应式设计和无障碍。请提供：组件架构、props 设计、实现代码和使用示例。
```

**建议：**明确写出“加载状态”和“边界情况”。AI 生成的组件经常默认遗漏这两项，所以要在提示词中明确要求。
