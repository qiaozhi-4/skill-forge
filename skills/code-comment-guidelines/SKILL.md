# 代码注释规范

用于新增、修改或审查源码中的注释。先根据文件类型读取对应参考资料，并按规则标注要求注释的声明。示例用于说明写法和位置，不是完整清单；函数体内避免逐行复述显而易见的实现步骤。

## 语言路由

根据源文件类型选择对应参考文档，每个文件只读取一份语言规则，不混用其他语言规则：

- C/C++（`.c`、`.h`、`.cc`、`.cpp`、`.cxx`、`.hh`、`.hpp`）：读取 [references/c-cpp.md](references/c-cpp.md)。
- Java（`.java`）：读取 [references/java.md](references/java.md)。
- JavaScript（`.js`、`.jsx`、`.mjs`、`.cjs`）：读取 [references/javascript.md](references/javascript.md)。
- TypeScript（`.ts`、`.tsx`、`.mts`、`.cts`）：读取 [references/typescript.md](references/typescript.md)。
- Kotlin（`.kt`、`.kts`）：读取 [references/kotlin.md](references/kotlin.md)。

## 通用要求

- 新增的注释必须使用中文；修改注释时也应使用中文表达。
- 语言规则明确要求注释的声明必须标注，即使含义已经由名称或签名表达；示例未展示某类声明，也不改变这项要求。
- 普通单行说明注释使用对应语言参考规定的语法，不要把某一种注释形式套用到所有语言；TypeScript 三斜线指令按编译语义保留，不要当作普通说明注释改写。
- 普通说明解释“为什么”、业务背景、限制条件和易错点，不重复代码、函数名或类型名已经表达的信息。
- 文档注释必须按声明完整提供适用的参数、返回值、异常或错误条件等标签（如 `@param`、`@return`、`@throws` 及对应文档工具的等价标签）；即使签名已表达相关信息也不得省略，描述必须与声明和实现一致。
- 公共 API 的文档注释要求按语言参考执行；行为、状态变化、线程安全、生命周期、异常、空值语义或平台约束不明显时，在文档中补充这些信息。
- 注释应贴近被说明的声明或逻辑，避免失效、空泛或与实现不一致的描述。
- 对非强制的实现说明，只在代码意图、业务原因、边界条件、生命周期、并发、资源管理、平台兼容或性能取舍不明显时添加。
- 不要为函数体内显而易见的代码、直观转换或普通布局逐行添加说明；声明注释义务以对应语言参考为准。
- 修改已有注释时，保持项目已有语言和表达风格；如果注释与代码不符，应一并修正。
